# Late Deliveries

Predict whether a QuickBite order will arrive more than 10 minutes late,
using information available when the order is placed.

The project uses 3,000 synthetic orders generated by the supplied,
unchanged `make_orders()` function. A flagged order receives a $4 voucher.
An unflagged late order costs $15.

## Setup

Run these commands in Anaconda Prompt:

```bash
git clone https://github.com/safi111287/lab05.git lab05-clone
cd lab05-clone
conda env create -f environment.yml
conda activate lab05-late-deliveries
python -m pip install -r requirements.txt
python -m pip install -e .
```

The environment uses Python 3.11. Package versions are pinned in
`requirements.txt`, which is saved as UTF-8.

For the notebook, open `notebooks/analysis.ipynb` in VS Code with the
Microsoft Python and Jupyter extensions enabled. Select the
`lab05-late-deliveries` kernel and run all cells.

## Run

Run from the repository root:

```bash
python -m latedeliveries.train
```

This command generates the data, compares models, tunes logistic
regression, selects a threshold using training predictions, evaluates
the final model, and saves:

- `reports/cv_results.csv`: cross-validation means and standard deviations.
- `reports/threshold_costs.csv`: training costs for each threshold.
- `reports/metrics.json`: final test metrics and policy costs.
- `models/late_orders.joblib`: the fitted preprocessing and model pipeline.
- `models/model_info.json`: scikit-learn version, seed, threshold,
  feature lists, best settings, tuning results, and test results.

The command recreates these outputs if they are missing.

To open the final metrics in Notepad on Windows:

```bash
notepad reports/metrics.json
```

The saved pipeline returns probabilities. Apply the threshold stored in
`models/model_info.json` to make voucher decisions; the pipeline's
default `predict()` method does not apply the selected 0.60 threshold.

Only load trusted joblib files, using the recorded package versions.

## Decisions

### Features and leakage prevention

Feature lists are defined once in `src/latedeliveries/pipeline.py`.

Numeric features:

- `distance_km`
- `items`
- `hour`
- `courier_months`

Categorical features:

- `weather`
- `day_type`
- `vehicle`

Excluded columns:

| Column | Reason |
|---|---|
| `order_id` | An identifier rather than a meaningful delivery predictor. |
| `prep_minutes` | Actual preparation time is unavailable when the order is placed. |
| `customer_rating` | Collected after delivery and therefore leaks outcome information. |
| `late` | The target, which must not appear among the inputs. |

Vehicle and courier experience are assumed to be available at order
placement. This assumption would need checking in a real system.

A stratified split reserves 25% of orders for testing: 2,250 training
orders and 750 test orders. `RANDOM_STATE = 7` controls the split,
shuffled cross-validation folds, and models with a random-state setting.

Numeric preprocessing uses median imputation followed by
`StandardScaler`. Categorical preprocessing uses
`OneHotEncoder(handle_unknown="ignore")`.

Preprocessing and classification stay together in a scikit-learn
pipeline. During cross-validation, preprocessing is fitted separately
inside each training fold.

### Model comparison

Models were compared using five-fold stratified cross-validation on
the training set only. Values below are mean ± standard deviation
across folds.

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Dummy | 0.8440 ± 0.0009 | 0.0000 ± 0.0000 | 0.0000 ± 0.0000 | 0.0000 ± 0.0000 | 0.5000 ± 0.0000 |
| Balanced logistic regression | 0.7387 ± 0.0159 | 0.3326 ± 0.0266 | 0.6722 ± 0.0653 | 0.4448 ± 0.0373 | 0.7881 ± 0.0368 |
| Decision tree | 0.8542 ± 0.0102 | 0.5957 ± 0.0875 | 0.2252 ± 0.0548 | 0.3221 ± 0.0627 | 0.7432 ± 0.0433 |
| Random forest | 0.8582 ± 0.0036 | 0.6721 ± 0.0335 | 0.1766 ± 0.0247 | 0.2792 ± 0.0329 | 0.7748 ± 0.0356 |

The dummy classifier always predicts on-time delivery. Its high
accuracy hides its failure to detect any late orders.

I selected balanced logistic regression for tuning because it had
the highest mean ROC-AUC and recall among the candidates. Missing a
late order costs $15, so detecting late orders matters more than
accuracy alone. Its threshold was then selected using the actual
cost rule.

These comparison metrics use each model's default classification
threshold. They do not establish that logistic regression has the
lowest achievable cost among all models.

### Hyperparameter tuning

`GridSearchCV` evaluated six combinations within the complete pipeline:

- `model__C`: `0.01`, `0.1`, `1`
- `model__fit_intercept`: `True`, `False`

The search used five-fold stratified cross-validation on training
data, with ROC-AUC scoring. ROC-AUC evaluates ranking across
thresholds, allowing the cost-based threshold to be selected separately.

Best settings:

```text
model__C = 0.01
model__fit_intercept = False
```

The best mean CV ROC-AUC was 0.7891, with a fold standard deviation
of 0.0373. The improvement over the original logistic model was
about 0.0010, much smaller than the fold variation. This is not
strong evidence of a meaningful performance gain.

### Threshold and cost

The cost function is:

```text
Total cost = 4 × (TP + FP) + 15 × FN
```

Every flagged order costs $4, including correctly flagged late orders.
An unflagged late order costs $15. An unflagged on-time order costs $0.

`cross_val_predict` generates out-of-fold training probabilities for
the selected model settings. Thresholds from 0.05 through 0.95,
in steps of 0.05, are compared using this cost function.

The selected threshold is **0.60**, with a training cost of **$4,172**.
If thresholds tie on cost, the higher threshold is selected.

The test set did not influence model tuning or threshold selection.
Class balancing means the model scores should not automatically be
interpreted as calibrated real-world probabilities.

### Leakage experiment

The notebook repeats training-only cross-validation after adding
`customer_rating` to a separate experimental pipeline.

| Inputs | Mean ROC-AUC | Standard deviation |
|---|---:|---:|
| Order-time features only | 0.7881 | 0.0368 |
| With customer rating | 0.9100 | 0.0140 |

Adding the post-delivery rating increases mean ROC-AUC by **0.1219**.
This apparent improvement is invalid for order-time prediction because
the rating is unavailable then and is related to the delivery outcome.

The experiment does not change the production feature lists or the
saved model. Customer rating remains excluded.

## Result

After fixing the model settings and threshold, the final pipeline
was fitted on all training orders and evaluated on the 750 test orders.

Confusion matrix: rows are actual outcomes and columns are predictions.

| Actual / Predicted | On time | Late |
|---|---:|---:|
| On time | 564 | 69 |
| Late | 67 | 50 |

| Metric | Test value |
|---|---:|
| Precision | 0.4202 |
| Recall | 0.4274 |
| F1 | 0.4237 |
| ROC-AUC | 0.7522 |
| Decision threshold | 0.60 |

ROC-AUC uses probability scores. Precision, recall, F1, and policy cost
use decisions made at the selected threshold.

| Policy | Cost on 750 test orders |
|---|---:|
| Flag nobody | $1,755 |
| Flag everybody | $3,000 |
| Selected model | $1,481 |

The model flags 119 orders, including 50 late orders and 69 on-time
orders. It misses 67 late orders.

```text
Model cost = 4 × 119 + 15 × 67 = $1,481
```

This saves **$274**, or **15.6%**, compared with flagging nobody.

I would consider a monitored pilot, but these synthetic test results
are not enough to trust the model for immediate real-world deployment.

## What the tests cover

The tests check:

- Exclusion of identifiers, unavailable columns, and the target.
- Selection of the intended input columns.
- Repeatable splitting, split sizes, stratification, and aligned labels.
- No overlap between training and test rows.
- Finite probabilities between zero and one that sum to one.
- Prediction with a missing numeric value and an unseen weather category.
- Median imputation learned from training data.
- Hand-calculated voucher and missed-late costs.
- Threshold selection, tie handling, and the threshold grid.
- Cases where flagging nobody or everybody is cheapest.
- Invalid probability values and mismatched cost-input lengths.
- Identical probabilities and predictions after saving and reloading
  the complete pipeline using `tmp_path`.

The suite uses a shared fixture in `conftest.py`, parametrized cases,
and `pytest.raises` with message matching.

An omitted area is an automated end-to-end test of `train.main()`
and every generated report. Current tests focus on pipeline behavior,
cost calculations, threshold selection, and persistence. The full
training command is checked separately during fresh-clone validation.

## Known limitations

- The data are synthetic and may not represent real delivery patterns.
- Results come from one fixed train/test split, without confidence
  intervals for the estimated savings.
- The model misses 67 of the 117 late test orders.
- Vehicle and courier information are assumed available at order placement.
- Voucher and missed-late costs are fixed assumptions; different costs
  could change the preferred threshold.
- Only six logistic-regression parameter combinations are searched.
- Hyperparameters are selected using the training set before generating
  out-of-fold threshold predictions. This is not nested cross-validation,
  so the training cost estimate may be optimistic.
- The selected threshold is restricted to a grid with steps of 0.05.
- Model probabilities are not explicitly calibrated.
- Output paths are relative, so training should run from the repository root.
- Reproducing results requires the same data generator, seed, code,
  and package versions.
